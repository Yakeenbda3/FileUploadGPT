<AnswerBox>
OpenAI's own wording is "all common file extensions for text files, spreadsheets, presentations,
and documents". There is no published list of extensions. Video and audio are not in those four
families. And on every plan except Enterprise, ChatGPT pulls the text out of a file and throws the
images away, which is why scanned documents come back with nothing.
</AnswerBox>

This question gets a lot of confidently wrong answers, mostly because people publish an extension
list that OpenAI never published. What OpenAI actually says is broader and vaguer than that, and the
useful detail is not in the list at all. It is in what happens to the parts of your file that are
not text.

## What OpenAI officially says

Asked directly what types are supported, the File Uploads FAQ answers in one sentence:

> All common file extensions for text files, spreadsheets, presentations, and documents.

That is the whole answer. Four families, no extensions, no table.

So any article handing you a definitive list of forty extensions has made it up, or inferred it from
testing, which is worth something but is not the same thing. The families are the official line, and
anything outside them is a guess until you try it.

## What works in practice

Within those four families, this is what holds up consistently.

| Family | Formats that work | Notes |
| --- | --- | --- |
| Documents | PDF, DOCX, DOC, RTF, ODT | Text-based PDFs only. See the images rule below. |
| Plain text | TXT, MD, CSV, JSON, XML, LOG | The most reliable of the lot. Nothing to go wrong. |
| Spreadsheets | XLSX, XLS, CSV | Exempt from the token cap that limits documents. |
| Presentations | PPTX, PPT, KEY | Text and structure come through, images do not. |
| Code | Almost any source file | Read as plain text, so the extension rarely matters. |

Code files are worth a note. There is no special handling for them, which is good news: a `.py`, a
`.rs`, a `.sql`, or something obscure is just text as far as the upload is concerned, and it goes
through fine.

## The images rule, which explains most failures

This is the part almost nobody covers, and it accounts for more confused uploads than anything else.

From the FAQ, on whether ChatGPT can handle images embedded in documents:

> All other plans and document files only support text-based retrieval. This means that ChatGPT will
> extract digital text from the file and discard any images.

Visual retrieval for PDFs exists only on ChatGPT Enterprise. On Free, Plus, Pro and Team, an upload
is stripped to its digital text and everything visual is dropped.

<Callout variant="warn" title="This is why your scanned PDF came back empty">
A scanned document is a photograph of a page. There is no digital text inside it, only pixels. So
"extract the text and discard the images" leaves exactly nothing. The upload succeeds, no error
appears, and ChatGPT tells you it cannot find anything, which sounds like a bug and is in fact the
documented behaviour.

The fix is OCR. Run the PDF through any OCR tool so it contains real text, then upload it. Adobe,
Preview on a Mac, and plenty of free web tools all do this.
</Callout>

The same rule explains why a chart in a report gets ignored, why a diagram in a slide deck goes
unmentioned, and why a Word document that is mostly screenshots produces a thin summary.

## Video and audio

Not in the four families. OpenAI's supported list names text files, spreadsheets, presentations and
documents, and neither video nor audio appears in it.

This trips people up because ChatGPT clearly does handle voice. That is voice mode, a separate
feature, and it is not the same thing as attaching an mp3 to a conversation for analysis.

If you have video or audio you need worked on, get a transcript first. Any transcription tool will
produce a text file, and a text file is the most reliably supported thing there is.

## Archives

Zip and RAR do not work, and the reason is simple: ChatGPT does not unpack them to see what is
inside. You have handed it a container it treats as one opaque file.

Extract it yourself and upload the files that matter. This also tends to produce better answers,
because you have removed everything irrelevant rather than burying the useful file among ninety
others.

## The size limits, which are separate

Being a supported type is not the same as being an acceptable size. Four different ceilings apply.

| Limit | Value |
| --- | --- |
| Any single file | <Fact k="maxFileSize" /> |
| Text and document files | <Fact k="maxTextTokens" />, spreadsheets exempt |
| CSV and spreadsheets | <Fact k="maxSpreadsheetSize" /> |
| Images | <Fact k="maxImageSize" /> |

The token cap is the one that catches people. A long document can be a few megabytes, nowhere near
the size ceiling, and still be past what fits. When that happens you usually get no error at all.
The file uploads, and ChatGPT works from part of it.

people hit "upload limit reached" having uploaded almost nothing recently.

## Working out whether your format will work

A rule of thumb that has not let me down: **if you can open it in a text editor and read words, so
can ChatGPT.**

Try that. If the file shows recognisable text, upload it as-is. If it shows binary noise, it needs
converting first, and the target is almost always PDF or plain text.

For anything genuinely unusual, converting is faster than testing. Exporting to `.txt` takes a few
seconds and removes the question entirely.
